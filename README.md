# 要件整合レビュー

公共提案業務のデモ用ワークスペース。画面・仕様書・判定基準の組織や案件はすべて架空です。

## 起動

Node.js 22.13以上が必要です。ZIPを展開したフォルダで実行します。

```sh
npm ci
npm run dev
```

ブラウザで http://localhost:3000 を開きます。API設定なしでデモ全機能を試せます。

PCでは比較しやすい表形式、幅700px以下では要件一覧と判定基準表がラベル付きカード形式になります。スマートフォンでも画面全体を横スクロールせず確認できます。

長い要件本文はPC・スマートフォンともに4行で折りたたみ、必要な項目だけ「全文を表示」で展開できます。保存・照合に使う原文は省略しません。

本番用の実行：

```sh
npm run build
npm run start
```

サーバー処理が必要なため、静的HTML配信のみの環境では動作しません。

## 90秒の評価手順

1. PDF・DOCX・XLSX・TXT・MD・CSV・JSONをアップロードするか、「架空のA市サンプルで試す」を選びます。
2. 資料種別・確認目的を選び、必要なら補足コメントを入力して「この資料から要件を抽出」を押します。サンプルでは10要件・5候補が表示されます。
3. 候補01の原文A/B、RULE-01、検出理由、両立に向けた構成案を確認します。
4. 「対応の選択肢」で、構成案・適用できる技術・発注者へ推奨する質問が同じ判定基準から提示されることを確認します。
5. 候補01を「両立しない」、候補02を「構成で対応可」、候補03を「保留」にします。質問書対象は1件です。
6. 候補01の判断理由に「中継区画の設置可否が仕様書に明記されていないため」と入力します。
7. 「質問文を生成する」。第3章(2)ア／第3章(2)イ、構成案、技術案、確認質問を含む質問だけが生成されます。「コピー」で取得できます。
8. 判定基準表を開き、RULE-01の条件Aに「,専用線必須」を追加して保存します。候補は4件に変わり、古い判断と質問は消去されます。
9. 元の条件に戻して保存すると、再び5候補になります。基準と結果の関係を確認できます。

効果の件数は実際の照合結果です。時間短縮率、検出精度、業務実績の架空の数値は表示しません。

## 判定の仕組み

- PDF：文字データを座標順に再構成します。文字データが少ないページは埋め込み画像を日本語OCRし、ページ位置を保持します。
- 抽出：第3章(2)ア、空白を含む階層、数値見出しに対応します。条番号がない資料はページ・本文単位で補完抽出します。要件IDは原文順です。
- 原文：抽出時の本文、条番号、行番号またはPDFページを保持します。照合時だけ全角・半角を正規化します。
- 照合：各基準について、条件A/Bのカンマ区切りキーワードをすべて含む異なる2要件を検出します。A/Bを逆順にしても検出し、同じ基準の同じ組み合わせは重複しません。
- 対応提案：両立に向けた構成案、技術アプローチ、確認質問の観点を判定基準表に保持し、該当した基準の内容だけを表示します。自由推論で新しい提案を追加しません。
- 初期基準：ネットワーク、個人情報、保守停止、段階稼働、費用、障害復旧、端末互換性、記録保存、サポート時間、遠隔保守の10観点を登録しています。
- AI：矛盾検出には使いません。接続時は分類と質問文の整形だけを担当します。文章は同じになる保証はありませんが、矛盾候補は同じ原文・同じ基準表で常に同じです。
- 質問API：クライアントからの候補を信用せず、原文と基準から候補を再計算して「両立しない」のみを採用します。条番号はサーバーが付与します。

### 制限

任意の体裁を完全に復元するものではありません。文字PDFは100ページまで、画像PDFのOCRは先頭から最大12対象ページまでです。パスワード保護・破損PDF、ページ全体が抽出可能な埋め込み画像になっていない特殊なスキャンPDFは読み取れない場合があります。OCR結果と本文単位の補完抽出は、提出前に原文と照合してください。

キーワードの部分一致は否定、同義語、例外条件、対象の違いを理解しません。該当なしは無矛盾の保証ではありません。誤検出・見逃しの両方を人が確認してください。

## AI接続

`.env.example`を`.env.local`へコピーし、以下をサーバーに設定してください。画面には接続先の実在製品名を表示しません。

| 変数          | 用途                                  |
| ------------- | ------------------------------------- |
| `LLM_API_URL` | HTTPSのチャット生成エンドポイント全体 |
| `LLM_API_KEY` | サーバー専用の認証キー                |
| `LLM_MODEL`   | 接続先が受け付けるモデル識別子        |

リクエスト契約は `{model, temperature, messages:[{role,content}]}`、レスポンス契約は `{choices:[{message:{content:"JSON文字列"}}]}` です。分類では `{"categories":["セキュリティ",...]}`、質問では `{"questions":["質問本文",...]}` を期待します。

3変数が揃うとAI接続モードになります。設定変更後はサーバーを再起動してください。接続失敗はエラーとして表示し、デモ成功に見せかけて切り替えることはありません。

APIキーに公開用の接頭辞を付けないでください。秘密値はソース・ログ・ZIPに含めません。外部AI接続時に限り、要件本文と質問素材が設定した接続先に送信されます。

## 構成

- `app/page.tsx`：サーバー側の接続状態と単一ページ
- `components/Workspace.tsx`：画面内状態、操作の連携
- `components/InputSection.tsx`：原文入力
- `components/RequirementsTable.tsx`：原文と出典の一覧
- `components/ConflictCards.tsx`：根拠の対比、人の判断
- `components/QuestionDraft.tsx`：質問文生成とコピー
- `components/RuleEditor.tsx`：基準編集・追加・再照合
- `lib/engine.ts`：決定的な抽出・照合・質問対象選別
- `lib/server.ts`：サーバー専用のAI呼び出し、入力サイズ制限
- `app/api/extract/route.ts` / `app/api/questions/route.ts`：API Route
- `lib/pdf.ts`：PDFの座標順再構成、埋め込み画像の日本語OCR、ページ位置の付与
- `app/api/document/route.ts`：アップロード文書からの本文抽出（5MB、PDFは100ページ、OCRは最大12対象ページ）

## 運用上の範囲

外部DB、ローカルストレージ、相談履歴保存、認証はありません。画面再読み込みで入力・判断・編集した基準は消えます。ローカル評価向けです。外部公開して有料AIを接続する場合、アクセス制限とリクエスト制限を配信環境側で設定してください。画面内の編集がサーバーの共有基準を変更することはありません。

復旧は、既知の正常なソース一式に戻して再ビルド・再起動します。データ移行はありません。設定値とキーの管理・更新は実行環境の管理者が担当します。

### セキュリティ

- APIは同一サイト検査、入力サイズ制限、インスタンス単位の流量制御を行い、レスポンスを保存しない設定です。
- PDF・DOCX・XLSXは拡張子に加えて先頭シグネチャを検査します。PDF OCRは5MB、100ページ、12対象ページ、2,500万画素、毎分4リクエストの上限を設けます。ただし、未知の解析ライブラリ脆弱性や圧縮爆弾を完全に防ぐものではありません。
- ブラウザにはCSP、クリックジャッキング防止、MIME推測防止、権限制限などのヘッダーを返します。
- LLM接続先はHTTPSを必須とし、代表的なローカル・プライベートアドレスを拒否します。接続先ドメインの許可リスト管理は配信環境の管理者が行ってください。
- 公開運用では、コード内制限に加えてVercel Firewall側でAPIレート制限を段階導入してください。
