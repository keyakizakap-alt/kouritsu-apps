# verification-before-completion — 証拠のない完了報告を出さない

**原則: 主張の前に証拠。例外なし。**

**文言を言い換えてこのルールを回避するのは、ルール違反である。**

## 鉄則

```
今このメッセージ内で検証コマンドを実行していないなら、
「通る」「直った」「完了」と言ってはならない。
```

## ゲート手順

```
何らかの状態を主張する／満足を表明する前に:

1. 特定 — その主張を証明するコマンドは何か
2. 実行 — フルコマンドを新規に実行する（前回の結果の使い回し禁止）
3. 読む — 出力全文・終了コード・失敗件数を読む
4. 照合 — 出力は主張を裏付けているか
   NO  → 実際の状態を証拠付きで述べる
   YES → 主張を証拠付きで述べる
5. ここで初めて主張してよい

いずれかを飛ばしたら、それは検証ではなく虚偽報告である。
```

## 主張と必要な証拠

| 主張 | 必要な証拠 | 不十分なもの |
|---|---|---|
| テストが通る | テストコマンドの出力（失敗0件） | 前回の実行結果、「通るはず」 |
| Lint / format クリーン | Lint コマンドの出力（エラー0件） | 一部だけ確認、推定 |
| ビルドが通る | ビルドコマンドの終了コード 0 | Lint が通った、ログが良さそう |
| 型が通る | `typecheck` の出力 | エディタが赤くない |
| バグが直った | 元の症状を再現する手順／テストが通ること | コードを変えた、たぶん直った |
| リグレッションテストが機能する | RED→GREEN を実際に確認 | テストが1回通った |
| 画面が動く | 実際に起動して該当操作を実行した記録 | HTML を読んだ、それらしく書けた |
| 要件を満たした | 受け入れ条件を1行ずつ照合したチェックリスト | テストが通った |
| サブエージェントが完了した | `git diff` に変更が出ている | エージェントの「成功しました」 |

## 停止シグナル（これを言いかけたら止まる）

- 「〜のはず」「おそらく」「〜と思われる」「問題ないはずです」
- 検証前に満足を表明する（「完璧です」「できました」「バッチリです」）
- 検証せずにコミット／プッシュ／PR作成に進もうとしている
- サブエージェントやツールの成功報告をそのまま信じている
- 一部だけの確認で全体を語ろうとしている
- 「今回だけは」
- **実行していないのに成功を含意する、あらゆる言い回し**

## 言い訳と現実

| 言い訳 | 現実 |
|---|---|
| 「たぶんもう動く」 | 実行して確かめる |
| 「自信がある」 | 自信は証拠ではない |
| 「今回だけ」 | 例外なし |
| 「Lint が通った」 | Lint はコンパイラでも型検査でもテストでもない |
| 「エージェントが成功と言った」 | 自分で diff を見る |
| 「疲れている」 | 疲労は免責にならない |
| 「部分確認で十分」 | 部分は何も証明しない |
| 「表現を変えたからルール外」 | 文言ではなく趣旨に従う |

## パターン

**テスト**
```
✅ [テスト実行] [出力: 12/12 passed] 「テスト12件すべて通過」
❌ 「修正したので通るはずです」
```

**リグレッションテスト（RED-GREEN の確認）**
```
✅ テスト作成 → 実行(pass) → 修正を戻す → 実行(必ずFAIL) → 修正を戻す → 実行(pass)
❌ 「リグレッションテストを追加しました」（RED を見ていない）
```

**要件**
```
✅ 仕様を読み直す → 受け入れ条件のチェックリスト化 → 1件ずつ照合 → 未達を明示
❌ 「テストが通ったのでフェーズ完了」
```

**静的サイト／ビルド不要のアプリ**
```
✅ 実際にページを開き、対象の操作を実行し、コンソールエラー0件を確認
❌ 「HTML を修正したので表示されるはずです」
```

## 報告できない場合の正しい振る舞い

環境の制約で検証できないときは、**「完了」と言わずに未検証であることを明示する**。

```
✅ 「実装は終わったが、本環境ではブラウザ実行ができないため動作未検証。
    確認手順は次のとおり: 1) ... 2) ... 」
❌ 「実装完了、動作するはずです」
```
